About

I got here by taking things apart

Before it was C#, it was redstone contraptions in Minecraft. Same pleasure, smaller scale: watching something absurdly complex finally click. In 2022 I started writing add-ons and plugins for Minecraft Java, realised programming was exactly that feeling, and went looking for heavier languages. I landed on .NET in 2023 and never left.

Between 15 and 19 I worked freelance assembling dark poultry houses and swine facilities: feeders, nipple drinkers, curtains, emergency openings, misting systems, exhaust fans, plumbing, water tanks. Follow the manual, test the sensors, no duct tape, hand it over working. I may look like a skinny dev, but I know what it's like to be out in the field and have to solve it right there.

At RGO I started in IT support, because that was the opening. A year in, I could see how much of the company could be fixed with code, so I asked for the role change, and got it. Today I'm on the dev team: we review each other's code, decide architecture together, and nothing ships without every party signing off.

I use AI the same way I use anything else on the belt. Coding agents and LLMs speed up implementation, refactoring and documentation, and they only work because the spec exists before the first prompt: a model without a spec produces fast and gets thrown away fast. I review and answer for every line that reaches production. The tool speeds up the typing, not the decision.

Outside of that: video games, board games, D&D, cooking something I've never made before, and an amount of coffee that would worry a doctor. I don't listen to music while I work; I end up listening to the music instead of working.

Work

Things I built that people use

Problem, decision, result. Everything below was built for production at an industrial machinery manufacturer.

RgoSystem

in production
The problem
The ERP doesn't cover everything the company needs. What it doesn't cover turns into spreadsheets and undocumented workflows that live in someone's head.
The call I made
Blazor Server, because the backend is already C# and I wasn't giving up end-to-end type safety to write a web app. Direct data access through EF Core instead of standing up an API microservice for a system that is centralised anyway; mapped to the last millimetre.
What changed
One place for the company's automations, with the workflows documented instead of improvised. Over 60 people use it daily, and it has never gone down on me.
C#.NETBlazor ServerEF CoreOracle

Protheus label printing

in production
The problem
Labels for incoming and internal materials were written by hand. The pen smudged, the label faded, and the shop floor lost track of what was what.
The call I made
Pull the data straight from the ERP and drive Zebra and Elesys printers from .NET, so a label is a consequence of the record, not a second, manual truth.
What changed
Labels come out printed, current, adhesive and legible. Receiving and internal shipping stopped guessing.
C#.NETZebraElesysERP integration

Microsoft 365 signature generator

in production
The problem
Email signatures were made by hand, one image at a time: heavy, inconsistent and outdated the moment someone changed roles.
The call I made
Generate them from the source of truth. Microsoft Graph already knows every user's data, so .NET renders the image from it.
What changed
100% automated, standardised across the company, transparent, crisply rasterised, and under 20 KB each.
C#.NETMicrosoft GraphMicrosoft 365

Azure delivery pipeline

infrastructure
The problem
Applications were published by building to a folder and ClickOnce, tied to local infrastructure, with no repeatable path from commit to production.
The call I made
Put a new ASP.NET app on Azure and build the whole path properly: resource group, app service plan, Key Vault, virtual network, NAT gateway with a fixed outbound IP, custom domain, and GitHub Actions deploying per branch.
What changed
A commit to the right branch became a deploy, end to end. It worked, and we still left Azure over performance; what I learned there went into the self-hosted setup in the next card.
AzureAzure DevOpsGitHub ActionsASP.NETKey Vault

Self-hosted platform in a DMZ

in production
The problem
The Blazor Server app ran fine on Azure, but the performance was not good enough for daily use, and the cloud setup was dropped.
The call I made
Build it in-house from zero: a Linux VM on Hyper-V with Ubuntu Server, Coolify managing the Docker containers, and the company firewall reconfigured with an internal DMZ network that points at that VM and nothing else.
What changed
The app runs on the company's own servers, reachable from outside on the company domain, with external traffic confined to the DMZ. And it is fast: performance stopped being a topic.
